## 一、核心命题

> 用户要的不是"练 SQL"，而是**学会大数据**。
> 大数据工程师的真实工作不是写单条 SQL，而是**把数据从 A 搬到 B，并且保证搬对了**。
> 所以产品要模拟的是**整条数据传输链路**，用户在链路的每一环写代码，系统校验代码是否正确、产物是否正确、链路是否跑通。

**"校验能过"三层含义（这是产品的技术核心）：**

| 层级 | 校验什么 | 举例 |
|---|---|---|
| **L1 代码正确** | 语法、必填参数、命名规范 | `sqoop import` 缺 `--target-dir` → 报错 |
| **L2 产物正确** | 产出的表/分区/文件是否符合期望 | 分区目录 `dt=20240601` 下应有 3 个 part 文件、共 4821 行 |
| **L3 链路正确** | 端到端数据是否一致、血缘是否完整 | 源表 12,000 行 → ODS 12,000 行 → DWD 去重后 11,842 行；金额合计必须相等 |

## 二、六层链路与可选题型

### 第 1 层 · 数据源（Source）

| 节点类型 | 模拟对象 | 用户写的代码 | 校验点 |
|---|---|---|---|
| `source_mysql` | 业务库（MySQL/Oracle） | 一条 SELECT（定义要抽取的数据范围） | 表/字段存在、语法正确 |
| `source_file` | 日志文件 / CSV / Excel | 文件路径 + 正则/分隔符解析规则 | 路径存在、解析出的字段数匹配 |
| `source_kafka` | 消息队列 | topic 名 + 消费位点 + 消息格式 | topic 存在、格式可解析 |
| `source_api` | 接口 | URL + 分页参数 + JSON 路径 | 字段提取路径正确 |

### 第 2 层 · 采集 / 同步（Ingestion）★ 用户最想练的

| 节点类型 | 工具 | 用户写的代码 | 校验点（重点） |
|---|---|---|---|
| `sqoop_import` | Sqoop | `sqoop import --connect jdbc:mysql://... --table X --target-dir /user/... --split-by id --num-mappers 4` | 参数完整性、表/字段存在、**模拟执行后的 VFS 分区目录与行数** |
| `sqoop_export` | Sqoop | `sqoop export --export-dir ... --table ...` | export-dir 必须已存在、目标表字段数匹配 |
| `datax_sync` | DataX | 一份 JSON 配置（reader/writer/channel/speed） | JSON 结构、reader/writer 类型匹配、字段映射完整、`channel` 合理 |
| `flume_agent` | Flume | conf 文本（source / channel / sink + interceptor） | 组件命名规范、source-channel-sink 是否串起来 |
| `canal_instance` | Canal（binlog 实时同步） | instance 配置（destination + filter 正则） | filter 语法、库表是否存在 |
| `kafka_connect` | Kafka Connect | connector JSON | 必需字段、topic 存在 |

### 第 3 层 · 存储（Storage）

| 节点类型 | 模拟对象 | 用户操作 | 校验点 |
|---|---|---|---|
| `hdfs_mkdir` | HDFS 目录 | `hdfs dfs -mkdir -p /user/hive/warehouse/ods.db/xxx/dt=20240601` | 路径规范（必须带分区目录） |
| `hive_create_table` | Hive 建表 | `CREATE EXTERNAL TABLE ... PARTITIONED BY (dt STRING) STORED AS PARQUET LOCATION '...'` | 字段类型、分区键、LOCATION 与 HDFS 目录一致、存储格式 |
| `hive_add_partition` | 分区挂载 | `ALTER TABLE ... ADD PARTITION (dt='20240601')` | 分区目录必须真实存在 |
| `hbase_create` | HBase 表 | `create 'table', {NAME=>'cf', VERSIONS=>3}` | rowkey 设计、列族 |

### 第 4 层 · 计算（Compute）

| 节点类型 | 工具 | 用户写的代码 | 校验点 |
|---|---|---|---|
| `hive_sql` | Hive SQL | `INSERT OVERWRITE TABLE dwd.xxx PARTITION(dt='20240601') SELECT ...` | ①方言可翻译 ②表/字段存在 ③**产物行数与期望一致** |
| `spark_sql` | Spark SQL | 同 Hive SQL + 分区覆盖语义 | 同上 + 小文件问题（part 文件数是否合理） |
| `spark_pyspark` | PySpark 作业 | Python 代码（df API 子集） | 语法 + 调用的算子存在 + 产物校验 |
| `mapreduce` | MapReduce | mapper / reducer 骨架 | 输入输出类型、分区数 |
| `flink_sql` | Flink SQL（流处理） | `SELECT ... FROM kafka_source` + 窗口函数 | 时间语义、窗口定义、水印 |
| `data_quality` | 数据质量校验 | 断言式 SQL（期望 0 行表示通过） | 校验规则本身是否正确、是否真能发现问题 |

### 第 5 层 · 调度（Orchestration）

| 节点类型 | 工具 | 用户操作 | 校验点 |
|---|---|---|---|
| `dag_schedule` | Airflow / DolphinScheduler | 拖拽或 YAML 定义 DAG：任务依赖 + cron | ①依赖无环 ②上游存在 ③cron 表达式合法 ④**上游失败时的下游行为** ⑤补数语义 |
| `dag_backfill` | 补数 | 指定日期区间重跑 | 分区覆盖是否正确、会不会重复写 |

### 第 6 层 · 输出 / 应用（Sink）

| 节点类型 | 模拟对象 | 校验点 |
|---|---|---|
| `export_mysql` | 结果回写业务库 | 目标表字段/类型匹配、主键冲突处理 |
| `export_clickhouse` | OLAP 库 | 引擎类型（ReplacingMergeTree）、分区键 |
| `export_es` | 搜索库 | 索引 mapping、字段类型 |
| `export_file` | 报表文件 | 文件名/格式/行数（可下载真实 CSV） |
| `bi_dashboard` | 看板 | 指标定义是否与 ADS 表一致 |

## 三、综合题：一条完整链路的关卡

> 这是产品的"大 Boss"——一个真实的业务需求，用户要**自己选工具、自己写每一步代码、把整条链路跑通**，系统做端到端校验。

### 关卡示例：营销部要一份"台区线损日报"

**需求原文（用户看到）：**

> 营销部每天早上 8 点要看昨天各台区的线损率。数据在业务库 MySQL 的 `meter_readings` 和 `customers` 里。
> 要求：① 每天增量抽取（只取昨天有抄表记录的数据）② 落到 Hive ODS 层（按 dt 分区）
> ③ 清洗后形成 DWD 明细（剔除估抄、处理表底跳变）④ 汇总成 DWS 台区日线损
> ⑤ 输出到 MySQL 报表库的 `rpt_line_loss_daily` 表 ⑥ 每天早上 8 点自动跑。

**用户需要完成的 6 个节点：**

| 节点 | 类型 | 用户要写的代码（要点） |
|---|---|---|
| 1 | `sqoop_import` | `--table meter_readings --where "period='20240601'" --target-dir /user/hive/warehouse/ods.db/meter_readings/dt=20240601 --split-by reading_id --num-mappers 4` |
| 2 | `hive_create_table` | ODS 外部表 + `PARTITIONED BY(dt STRING)` + `STORED AS PARQUET` |
| 3 | `hive_sql` | `INSERT OVERWRITE TABLE dwd.meter_readings_di PARTITION(dt='20240601') SELECT ... WHERE read_type <> '估抄'`（**关键：处理换表跳变**） |
| 4 | `hive_sql` | `INSERT OVERWRITE TABLE dws.transformer_loss_1d PARTITION(dt='20240601') SELECT ...`（线损率计算） |
| 5 | `export_mysql` | 回写 `rpt_line_loss_daily` |
| 6 | `dag_schedule` | 依赖链 `1→2→3→4→5`，cron `0 8 * * *` |

**系统校验（全绿才算通关）：**

```
✅ 节点1 语法/参数校验通过；模拟执行产出 4 个 part 文件、4821 行、分区目录正确
✅ 节点2 表结构校验通过；LOCATION 与节点1的 target-dir 一致（一致性检查！）
✅ 节点3 产物校验：行数 = 源表行数 - 估抄行数（精确到行）
✅ 节点4 产物校验：抽样 5 个台区的线损率与参考答案误差 < 0.01
✅ 节点5 目标表行数、字段类型匹配
✅ 节点6 DAG 无环、依赖完整、cron 合法
✅ 端到端一致性：源表金额合计 = ADS 层金额合计
✅ 血缘图完整（每个产物的上游可追溯）
```

## 四、模拟执行引擎（技术核心）

**核心洞察：整条链路都可以在浏览器里用「SQLite + 虚拟文件系统 + 虚拟时钟」模拟，不需要任何真实集群。**

| 真实世界 | 本训练场的模拟方式 |
|---|---|
| MySQL / Oracle 业务库 | SQLite 里的一组表（`ods_` 前缀或独立 attached 库） |
| HDFS | 内存目录树 `VFS`（已有实现：`src/lib/vfs.mjs`），文件带 format/rows/bytes/partition 元数据 |
| Hive 数仓 | ① 元数据：表名/字段/分区/存储格式/位置（`src/lib/hive.mjs`）② 数据：SQLite 中的 `db.table` 同名表 |
| Hive SQL / Spark SQL | 方言翻译层（已有：`src/lib/dialect.mjs`）→ 在 SQLite 上执行 |
| Sqoop import | 解析命令 → 生成等价 SELECT → 执行 → 在 VFS 写分区目录与 part 文件 |
| DataX | 解析 JSON → 按 reader/writer 生成等价 SQL 搬运 → 写 VFS / SQLite |
| Flume | 解析 conf → 校验组件串联 → 模拟"日志行数 = 写入 HDFS 行数" |
| Kafka | 内存消息队列：topic + 分区 + offset + 消息体（可回放） |
| 调度 DAG | 任务图 + 虚拟时钟推进；支持依赖、失败传播、补数 |
| MapReduce 分片 | 按 `--split-by` 值域把行切成 N 片（part 文件数 = split 数） |
| 集群资源 | 模拟：mappers 数、队列、执行耗时估算（让人有"性能"的体感） |

### 4.1 校验器注册表（可扩展）

每种节点类型注册自己的校验函数，统一接口：

```js
validator = {
  type: 'sqoop_import',
  // ① 静态校验：不改数据，只看代码
  lint(code, node, ctx) -> { errors: [], warnings: [] },
  // ② 语义校验：对象是否存在（表/字段/路径/topic）
  resolve(code, node, ctx) -> { plan: {...}, errors: [] },
  // ③ 模拟执行：真的跑
  run(plan, ctx) -> { outputs: [{vfsPaths, hiveTables, rows, metrics}], logs: [] },
  // ④ 产物校验：与题目期望比对
  check(outputs, expect) -> { status:'pass'|'close'|'fail', details: [] },
}
```

**四层校验的价值**：用户得到的不是"错/对"，而是**具体哪一层错了**——
`lint` 挂 → "你少写了 --target-dir"；`run` 挂 → "表不存在"；`check` 挂 → "行数差了 137 行，是不是没剔除估抄？"

### 4.2 血缘（Lineage）

每个节点执行后登记产物 → 自动生成血缘图：

```
ods.meter_readings(dt=20240601)  ←  sqoop_import (源: mysql.meter_readings)
        ↓
dwd.meter_readings_di(dt=20240601)
        ↓
dws.transformer_loss_1d(dt=20240601)
        ↓
mysql.rpt_line_loss_daily
```

血缘图用于：① 校验链路完整性（题目要求"必须经过 DWD 层"，绕过去就判不过）② 出错时反向定位 ③ 可视化教学。

## 八、诚实边界（必须写在产品里，不能骗用户）

这是**教学模拟器**，不是真集群。要在首页明确标注：

| 我们的模拟 | 真实世界 |
|---|---|
| SQLite 当 Hive/Spark 引擎 | 真集群是 Hive on Tez/Spark on YARN |
| 内存目录树当 HDFS | 真 HDFS 有副本、block、NameNode |
| 虚拟时钟推 DAG | 真调度器有 executor、队列、资源竞争 |
| DataX/Flume 只校验配置 + 模拟产物 | 真工具与数据源驱动强绑定 |

**这样做的理由（也是卖点）**：真实集群要 8 台机器 + 3 天搭环境，劝退 99% 的初学者。而**数据链路的核心难点在于"想清楚怎么搬、搬对没有"，不在于装 Hadoop**。把安装门槛去掉，把链路思维留下——这是本产品存在的意义。

配套：每个知识点提供"真机迁移指引"——告诉用户这些代码在真实环境里怎么跑、还需要注意什么（如 YARN 队列、小文件合并、数据倾斜）。
